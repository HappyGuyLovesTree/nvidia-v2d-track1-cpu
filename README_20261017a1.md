## Fixed scope and dependencies

The numerical recipe remains the original C2 for the old23 and the eventual real C3 for the new7. `manifests/recipe_c2.json` preserves C2's exact numeric signature, assets and constants. All actual producers remain separate from recipe commits, importers and final stock packing.

The environment lock targets CPython **3.12.7**, **macOS arm64** and the recorded CPU numerical stack. Use `requirements-macos-arm64-py312_20261017a1.lock`: it pins all24 distributions in the active dependency closure with a SHA256 for the exact official PyPI wheel tag matching the installed distribution. Optional extras and Linux GPU packages are excluded by the actual marker environment. The environment manifest records dependency edges, constraints, wheel URLs, installed metadata/RECORD hashes, verified file counts and individual license texts. Every selected installed RECORD matched its files during capture.

OpenCV is `opencv-python-headless==4.13.0.92`; the actual cv2 module and binary match its RECORD. The installed `opencv-python==5.0.0.93` metadata was stale and is excluded. Model files were never opened by dependency inspection. Metadata and official wheel hashes were fetched; wheel archives were not downloaded and a fresh environment was not installed in this task. The earlier unresolved lock/manifests are retained preparation history; the a1 files are current.

On a new compatible Mac, create an isolated environment with Python3.12.7 and install using:

```sh
python -m pip install --only-binary=:all: --require-hashes -r requirements-macos-arm64-py312_20261017a1.lock
python tools/check_environment.py --lock manifests/environment_macos_20261017a1.json --verify-files
```

These installation commands were not executed in this task. `--strict-installed-record` is an additional check for the exact recorded existing installation. A fresh pip install can regenerate RECORD bookkeeping, so its byte identity is reported separately from the fixed version/METADATA and current per-file checks. This does not assert numerical equivalence across machines.

`ffprobe` is a separate native dependency; see `manifests/ffprobe_macos_20261017.json` for actual version, binary hash and build flags. No automatic installation occurs. Python-wheel completeness does not imply ffprobe's native shared libraries or another OS have been reproduced. Use the recorded Mac toolchain when interpreting differences.

## Configure paths and inspect fixed assets

Pass a fresh external workspace with `--workspace`; `paths.example.json` contains no private absolute path. For already available local assets, copy that file to a local configuration and set explicit `asset_overrides` by key. Supported keys include `kit`, `nanodet`, `hmr`, `rig`, `semantics`, `sample`, and `video_000000` through `video_000029`. `python_extra_sites` is only for explicit existing package targets such as the separated mesh packages. A clean installed environment can leave it empty. Runtime configurations and receipts belong outside the source repository.

```text
python tools/assets.py plan --manifest manifests/external_assets.json --roster manifests/input_roster.json --paths paths.example.json --workspace <workspace>
python tools/assets.py verify --manifest manifests/external_assets.json --paths <local-paths.json> --workspace <workspace> --key nanodet
```

`plan` and `verify` do not download. Explicit `fetch --key ...` is implemented for fixed HTTPS assets and videos. It uses system curl with TLS validation, no curlrc, no retry, fixed byte/hash checks and a bounded transfer; no model is loaded. A failed transfer keeps partial evidence and never silently retries or overwrites an existing target. Do not commit any runtime asset or receipt.

```text
python tools/assets.py fetch --manifest manifests/external_assets.json --paths paths.example.json --workspace <workspace> --key kit
python tools/assets.py unpack --manifest manifests/external_assets.json --paths paths.example.json --workspace <workspace> --key kit
python tools/assets.py fetch --manifest manifests/external_assets.json --paths paths.example.json --workspace <workspace> --key rig
python tools/assets.py unpack --manifest manifests/external_assets.json --paths paths.example.json --workspace <workspace> --key rig
```

Kit downloads go to `downloads/kit.zip`; the ZIP's own root becomes `external/v2d_submission_kit`. MHR downloads go to `downloads/rig.zip`, then only the fixed `assets/mhr_model.pt` member is extracted and checked into the external model target. ZIP traversal, symlinks, duplicate names, wrong sizes/hashes and extraction caps are checked. `sample` is a kit member: obtain it by fetching/unpacking the kit. Model/video downloads above were not run during this task.

## Public input and full original-frame PTS preparation

`manifests/input_roster.json` contains all30 fixed dataset paths/content hashes, declared stream/frame properties and required original-frame runs. `prepare_inputs.py` verifies the fixed official sample and checks exact required frame sets. It does not use sample xyz as ground truth. Original source boundaries are the contiguous runs of required original-frame numbers.

```text
python tools/prepare_inputs.py plan --roster manifests/input_roster.json --paths paths.example.json --workspace <workspace>
python tools/prepare_inputs.py verify --roster manifests/input_roster.json --paths <local-paths.json> --workspace <workspace> --episode 16
python tools/prepare_inputs.py pts --roster manifests/input_roster.json --paths <local-paths.json> --workspace <workspace> --sample <kit>/data/track_1_sample_submission.parquet --ffprobe <ffprobe> --episode 16
```

The `pts` command performs a full ffprobe pass over original frames. It records the actual executable, arguments, exit, stdout/stderr, ordinal/PTS map, stream, time base, counts, required coverage, before/after video identity and checker hash. It rejects absent/nonmonotonic/duplicate PTS, wrong intervals/count/stream, stderr errors or changed input bytes. Its direct child has finite wall/output limits and a saved terminal receipt. This child helper does not claim to replace C3's inference process-tree supervisor.

It writes immutable `preparation/episode_XXXXXX_<token>/whole_pts.json` and `episode_input.json`, plus a new preparation index. The episode schema is `r12_public_episode_input_v1`; its paths/hashes/checker are new facts, not relabelled C2 receipts. No model or historical budget is created. Missing official-independent binding remains pending even if local hash and PTS pass. `--bindings` accepts the normalized interface in `manifests/inference_interface.json`; source identity/hash and referenced response files must match. The final source task's actual evidence needs a deliberate schema adapter if its names differ.

## Run the unchanged official writer

`official_pack.py` validates six-array dimensions/finiteness/rotations, masks, hashes and the complete sample; it calls the fixed stock CLI in a separate process. It does not monkeypatch `pack.write`. It checks kit Python files and key sample/notice members against the fixed39-file manifest before and after. Each run writes a new candidate/receipt under `packs/<token>/` and verifies exact key order, uniqueness, finite xyz, five columns and uniform URL.

```text
python tools/official_pack.py plan --paths <local-paths.json> --workspace <workspace> --episodes <verified30-view> --masks <mask-directory> --provenance <final-provenance.json> --kit-manifest manifests/stock_kit.json --build-source <actual-clean-C4-checkout> --commit https://github.com/<owner>/<repo>/commit/<actual40sha>
python tools/official_pack.py run  --paths <local-paths.json> --workspace <workspace> --episodes <verified30-view> --masks <mask-directory> --provenance <final-provenance.json> --kit-manifest manifests/stock_kit.json --build-source <actual-clean-C4-checkout> --commit https://github.com/<owner>/<repo>/commit/<actual40sha>
```

Official mode requires full30/9877/740780, the actual clean build checkout matching that full40 URL, masks and finalized per-episode provenance (`r12_public_provenance_v1`). Entries must carry actual prediction producer/tree, imported boolean, input/required/NPZ/mask/OBJ hashes and final pack producer. The source/new7/import adapter is pending C3. The packer itself does not verify GitHub account/access, Kaggle entry/quota or a public leaderboard row; those remain external task gates. No upload command exists here.

`--scope fixture` is explicit and always reports `submission_ready=false`, no actual pack producer, and fixture scope. It cannot pass as an official full30 run. The zero-model test actually invoked the unchanged official stock writer on8281 synthetic rows, with generated arrays and a cube OBJ; it did not pack the real candidate or load a model/video.

## Direct-child cleanup correction (2026-10-17)

I12-PUB01 is corrected in `run_logged`. The main exception, cleanup poll, kill, bounded wait, log reference/close and receipt-write errors are preserved separately. Every wait has an explicit timeout; post-failure cleanup gets a separate finite allowance (default2 seconds), with no automatic second kill or PID/name/group lookup. An unknown cleanup poll causes no signal. If the child cannot be reaped, status stays failed/unconfirmed and moving logs are not hashed as final files.

The helper always reaches its terminal-record attempt in `finally`. A terminal write error triggers a separate exclusive fallback receipt; if both writes fail, it returns the complete failed result and attempts stderr without claiming a durable file exists. This does not extend the helper into an inference process-tree supervisor. The correction was checked with fault-only fake Popen objects and owned dummy process regressions; no production process was signalled.
