# R012 生产续算接口

日期：2026-10-17。只支持 `production_resume`。旧23条保持 C2 数值来源；公共 fresh replay 交独立 staging 实现。本入口不自动创建 fresh 空预算。

使用 `${PYTHON_EXECUTABLE} -B`，工作目录为本 source。所有输入路径均显式传入。不要直接调用旧 `r11.py prepare/run` 延长时窗。不得改变原 manifest/config 或依赖。

## 零模型准备

```sh
PY=${PYTHON_EXECUTABLE}
SRC='${LOCAL_PROJECT_ROOT}/DD/生产/track1/source'
EVID='${LOCAL_PROJECT_ROOT}/DD/证据/T012.05'
ROOT='${LOCAL_PROJECT_ROOT}/DD/实验/T012.05_R012_C3_20261017'
"$PY" -B "$SRC/r12.py" chain --output "$EVID/parent_chain_20261017.json"
"$PY" -B "$SRC/r12.py" audit-owners --chain "$EVID/parent_chain_20261017.json" --output "$EVID/historical_handover_20261017.json"
"$PY" -B "$SRC/r12.py" init --root "$ROOT" --chain "$EVID/parent_chain_20261017.json" --handover "$EVID/historical_handover_20261017.json" --authorization '${LOCAL_PROJECT_ROOT}/DD/任务/T012.05_任务卡_20261017.md' --diff "$EVID/source_diff_20261017.patch" --minutes 150
"$PY" -B "$SRC/r12.py" import23 --root "$ROOT"
"$PY" -B "$SRC/r12.py" status --root "$ROOT"
```

以上 chain/handover/init 的目标必须尚未存在。已初始化时直接复用本根，不重复 init、不新开根。链文件引用冻结 C1/C2 证据，祖先账不复制成当前 journal；本轮父基数只取 C2 total 一次。导入复制四类最终产物，原 NPZ/OBJ/mask/mesh 字节不变，复制和元数据都计额，绝不构造新 worker receipt。旧输入的字节验证来自冻结 PTS/hash链和当前文件大小；生产新7条沿原 worker 完整核视频 hash。

`audit-owners` 新增实时核查/接续回执，不修改历史 owner/end。没有 end 的历史登记身份只有在此独立核查确认该身份已不在场后可接续；未知/权限失败拒绝。核查范围仅登记对象，C22历史退出/reap始终 unverified。

唯一全局登记在 `DD/生产/track1/r12_control`；切换 session 不能切 root、改父链或重建 ledger。未闭合 load(frame=null)、任何 pending/removal、已锁存资源 stop、worker/controller未知或失败均阻断。禁止按年龄自动删锁或回执来恢复。真实失败须交总控独立核查；本入口没有自动重试或自动解锁命令。

## 独立验收后由 T012.06 创建实际生产时间

总控交付 `r12_production_release_v1` JSON。必须包含真实 `code_commit`、`active_root`、`sup_acceptance="passed"`、`ses_budget_import_acceptance="passed"`、`independent_evidence_refs=[Ref,...]` 和 `allowed_episodes`。首次只放行 `[28]`；episode28通过后再放行剩余六条。不能把本任务自测文件自行当独立放行证明。

```sh
"$PY" -B "$SRC/r12.py" new-session --root "$ROOT" --authorization '/绝对路径/总控正式执行任务卡.md' --diff "$EVID/source_diff_20261017.patch" --release '/绝对路径/总控独立放行.json' --minutes 150
"$PY" -B "$SRC/r12.py" run --root "$ROOT" --episodes 28
# ep28独立门槛通过后，以包含23—29的真实新放行文件再new-session。
"$PY" -B "$SRC/r12.py" run --root "$ROOT" --episodes remaining6
"$PY" -B "$SRC/r12.py" aggregate --root "$ROOT"
"$PY" -B "$SRC/r12.py" status --root "$ROOT"
```

`new-session` 每次以实际调用时间生成新时窗，原 ledger、复制字节、unknown和stop持续保留。默认150分钟；可显式选10—360分钟工程session，不是用户整体截止。清理参数 grace/TERM/KILL各5s、total20s、遥测2次共1s；candidate_stop后留90s，freeze后留45s。stage wall/RSS仍A2400s/2GiB、B1800s/2GiB、C360s/3GiB。全DD按原01:06:03 cutoff核4GiB，磁盘和64MiB回执余量另查。超出工程时窗只交准确partial，新时窗仍承接原账。

预期无额外失败时：父detector/HMR/rig=8319/8319/16638、三种load各24。新7最低1798/1798/3596、三种load各7；预计10117/10117/20234，各load31。caps10240/10240/20280、各load35。失败和unknown不退款，剩余rig仅46次，禁止自动整条重跑。

`run`/`aggregate`只接收已通过独立放行的23—29；旧16由导入的240帧完成层满足前置。每阶段必须同时有真实stage receipt、监督passed和controller最终passed。stage completed不替代进程退出/reap。worker入口还核global owner真实父进程链、session和release。

汇总仅在旧0—22与新23—29恰为全30时执行。新建`export_views/<uuid>`，逐文件复制并核hash，产出`view.json`及全740780行本地L1 pack；原23数值producer=C2，新7=实际C3，导入/控制/导出commit单列。仍`submission_eligible=false`，正式stock writer/公共URL由后续发布提交任务负责。

## 持久化失败门槛

I12-SUP01修正：发布terminal前先持久化`.commit_pending`。terminal写入及其fsync成功后才移除guard。发布后出现受控失败时guard保留，`read_attempt`返回unknown，worker和controller准入均拒绝。移除后不再执行可能失败的持久化动作。断电可能让guard重新出现并导致保守拒绝；不承诺断电原子成功，也不据磁盘孤立passed JSON绕过reader。
