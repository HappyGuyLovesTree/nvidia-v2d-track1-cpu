# T1 release code and numerical reproduction

Date: 2026-10-30. This is the full release source composition: unchanged historical R0 public baseline, the portable T1 numerical producer, and persistent-evidence full conversion/stock/receipt gates. A local commit and full-package evidence are recorded outside source; this document does not guess its own future commit hash.

## Reproduce the numerical method

1. Obtain the fixed videos, metadata and model assets, then produce a fresh R0 reconstruction using the existing `tools/reproduce.py` workflow. Preserve original controls/raw/B plans, call journals and exported six arrays/masks/OBJ/mesh NPZ. See `README_PUBLIC_C4_20261017a3.md` and the asset manifests/licenses.
2. Follow `t1_numerical/README_20261030.md`. Supply a path-free source checkout and a private caller dataset manifest. `portable.py plan` builds P scope and T1 statistics from the original-format R0. `portable.py run` explicitly requires a rig path, cap and model-execution flag, and produces every trial including rejections. It never reads a private list of accepted deltas as its answer.
3. Independent quality review and a full production contract remain separate. The numerical producer does not grant a human quality pass or send to a competition. The fixed production protocol here is `prospective_all_A_proposals`; original development20/independent12 retain zero-trigger/NA states.
4. `tools/t1.py` consumes frozen producer artifacts under a private exact contract, verifies the original source/call closure and retained rig/native/raw/input identities, copies the full arrays with only accepted q-z/t-z changes, and invokes the unchanged official stock packer. See its CLI help and the dated integration README for entry points.

The producer is run as a separate process to avoid flat-module name collisions with the baseline. Private paths and generated manifests/results never belong in this repository. A relocated or fresh baseline has its own producer/run/path identities; do not relabel it as historical C2/C3 or claim identical historical file hashes.

## Source attribution and current production

`t1_numerical/t1.py`, `planner.py`, `restricted_json.py` and `geometry_d.py` preserve their numerical source files byte for byte. Normalization, R0 schema checks and the monitor/call function bodies have documented preserved relationships; new portable IO/entry code has its own source tree. Retain the baseline LICENSE, licenses/, asset acquisition terms and the additional producer NOTICE. No weights, original videos, identity arrays, predictions or complete private journals are distributed.

The actual historical R0 C2/C3 producers, statistical A execution tree, actual private D execution tree, portable package tree and current converter/build commit are different identities. Current full conversion reuses independently reviewed persistent D outputs and performs zero new HMR, rig, detector or video decode calls. That reuse is disclosed in runtime provenance; it is not fresh all30 inference by this checkout.

The portable handoff has model-free numerical equivalence, relocation and original-format CLI fixtures. Its real Torch/fresh-R0 end-to-end replay was not run by the handoff task. The release full package has its own actual stock/roundtrip/difference/resource receipts, and requires separate independent complete-package acceptance. No source-only fixture establishes a new Kaggle score, external publication or submission.

## Scope and external actions

Public reproduction is a numerical recipe, not a promise to reproduce private run identifiers, independent annotations or an acceptance receipt. Production contracts pin exact data/source/policy/model/run references. Historical two-method failures and original limitations remain. The 2px budget measures added displacement, not pixel GT error; a local small-set pass is not a claim of global accuracy.

The send gate is CD-H-only, with immutable snapshot, exact final argv, independent full receipt, same-commit public access, fresh authorized account/team evidence and deduplication. It writes one intent before any upload; unknown outcomes are queried, never blindly resubmitted. This release-preparation phase performs no push or upload.
